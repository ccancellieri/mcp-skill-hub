# Input compression and modular context: bounded experiment

Measured on 2026-09-29 with Python 3.12 and `tiktoken` 0.12.0,
`o200k_base`. Fixtures are synthetic and generated by the versioned scripts.
No live memories, models, provider credentials or remote fallbacks are used.
These are text-payload and fidelity measurements, not completed-task savings.

## Deterministic input compression

`input_compression.py` exercises the real `compress_payload` API with its
default threshold (200 approximate tokens, using four characters per token).
It separately runs the explicit lossy option. Tokenization and validation are
outside the timed interval; seven calls follow one warmup per case.

| Synthetic input | Tokens before | Safe tokens after | Outcome |
| --- | ---: | ---: | --- |
| Formatted JSON, 100 records | 5,102 | 3,402 | JSON whitespace removed |
| Nested JSON with duplicate keys and numeric lexemes | 1,559 | 1,133 | JSON whitespace removed |
| English prose with negations, paths and numbers | 1,485 | 1,485 | Exact pass-through |
| Italian prose with negations, paths and numbers | 1,755 | 1,755 | Exact pass-through |
| Python source | 1,448 | 1,448 | Exact pass-through |
| Repeated logs | 399 | 399 | Exact pass-through |
| Already compact JSON | 3,402 | 3,402 | Exact pass-through |
| Small JSON below the default threshold | 12 | 12 | Exact pass-through |
| **Total for this corpus** | **15,162** | **13,036** | **2,126 fewer tokens (14.02%)** |

The corpus mix determines that aggregate; it is not an expected saving for
ordinary prose prompts. Safe compression preserves JSON object-pair ordering,
duplicate keys, numeric spellings, and string lexemes. Unsupported inputs are
unchanged. The original formatting is not preserved when JSON is minified.

With explicit lossy opt-in, repeated logs shrink from 399 to 18 tokens; the
corpus total becomes 12,655. The output is labeled lossy and is not treated as
reversible. Safe mode remains unchanged. Observed median compressor-only
latencies were below 0.8 ms on this machine; this excludes startup, retrieval,
tokenization and tool transport and does not qualify the hook deadline.

## Modular retrieval

`modular_context.py` seeds six scoped memory modules plus a foreign-project
copy. It calls the real composer preparation and expansion functions, projects
an experimental metadata-only index, then follows fixed schedules of zero,
one, two or six reads. The projection keeps source/project references, warnings,
review state and a mandatory compatibility constraint. Opaque IDs and the
fixture clock are fixed; each result records its corpus SHA-256.

The baseline is a lean JSON source/text packet containing all six modules,
not the larger current composer response. The table counts each distinct
index, tool-call request and complete expansion response once. It excludes
the unchanged prompt, tool schemas, protocol framing, reasoning and final answer.

| English fixture | Full source packet | Index only | Index + one read | Index + two reads | Index + all six reads |
| --- | ---: | ---: | ---: | ---: | ---: |
| Six short decisions | 190 | 360 | 602 | 848 | 1,828 |
| Six longer decision modules | 2,182 | 373 | 944 | 1,514 | 3,821 |

For longer modules, one read reduces this distinct payload by 56.74%; two reads
by 30.61%; reading everything increases it by 75.11%. For short decisions,
the index alone is larger than the full packet. Italian prompts show the same
trade-off: 949, 1,524 and 3,851 tokens for one, two and six long-module reads.
Zero reads do not supply the hidden rules and are not counted as task success.

Sequential tool use can replay previous context on subsequent model turns.
An illustrative uncached accounting for the English long-module fixture gives
1,337 input tokens through one read and 2,861 through two reads, versus 2,192
for one initial full-packet turn including its prompt. These are explicitly
different illustrative turn schedules, not equivalent completed tasks or billing.
The model may batch reads; caching and client history handling vary.

All requested source texts were recovered exactly, foreign-project fixtures
were excluded, the original prompts were preserved, and expansion rejected a
source changed after preparation. These checks do not measure whether an LLM
chooses the necessary modules or follows their constraints.

The current composer returns 1,349/1,386 tokens for the short English/Italian
cases and 2,789/2,826 for the long ones. **The compact index is an experimental
caller-side projection, not a shipped MCP response.** The composer also loads
all source bodies internally; this experiment establishes no I/O or RAM saving.
Safe compression leaves the already compact full-packet JSON unchanged.

## Decision and next gate

Keep short mandatory constraints visible. Use optional referenced modules for
longer background decisions; do not generate a new skill merely to wrap every
memory. Existing description-first skill lookup already offers part of this
pattern. Before implementing automatic module selection, compare actual client
tasks with eager context and on-demand context, including additional reads,
missed constraints, retries, cache usage and final correctness. A metadata-only
response must preserve scope, freshness, omissions and review requirements.

No production behavior, hooks, provider settings or default enrichment changed.
No LLM synthesis or model-driven selection was measured. These results do not
meet the whole-task promotion gate and do not warrant a promotional claim.

## Reproduce

Install the project/test dependencies plus `tiktoken==0.12.0` in the benchmark
environment (it is not a runtime dependency), and provision a verified offline
`o200k_base` tokenizer cache as required by `context_compare.load_tokenizer`.
Then, from the repository root:

```sh
export TIKTOKEN_CACHE_DIR=/path/to/verified-tokenizer-cache
python benchmarks/input_compression.py --output /tmp/input-compression.json
python benchmarks/modular_context.py --output /tmp/modular-context.json
python -m pytest tests/test_input_compression_benchmark.py tests/test_modular_context_benchmark.py tests/test_compression_integrity.py tests/test_context_composer.py tests/test_skill_retrieval.py -q
```

The targeted suite passed 30 tests with the verified cache present. Four
benchmark tests explicitly skip if that offline artifact is unavailable; they
do not download it. Token/fidelity results should reproduce with the pinned
code, corpus and tokenizer; latency samples naturally vary.
